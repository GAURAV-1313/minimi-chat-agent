minimi: how a turn works

A chat agent with one tool, web search, and a dated memory of every answer. Code handles everything that can be exact: dates, memory lookup, number checks. The models do only what needs judgment.

Plain code (deterministic, ~0 ms) Claude Haiku 5.5 (fast, cheap) Answer model, chosen per turn: Haiku / Sonnet 5.5 / Opus 5.5 SQLite on the user's machine

1 · The turn pipeline

One planner call, one writer call, no sub-agents. The planner picks the turn type, and the turn type picks the writer: Haiku for chat, Sonnet for research, Opus for "what changed since" re-checks. Those were chosen by eval, not taste. The writer runs its searches server-side, several at once when the question has several parts.

  • Why a planner at all? Our earlier chatbot scored 4/28 on small talk until small talk got its own path ahead of search. Haiku decides in about two seconds, so "hi" never costs a search.
  • Why one writer and not sub-agents? Across our past research runs, a sub-agent took a median 8.6 minutes. Parallel tool calls inside one model call give the same breadth in seconds.
  • Why a code guard and not an LLM judge? A judge panel once passed six numbers that were all wrong. String matching costs nothing and adds no time. The first version flagged 36% of turns, nearly all false alarms caused by the API cutting excerpts at about 150 characters. It now flags only numbers missing from a complete excerpt: 6 flags across 428 replayed turns, all fair on hand review.
  • Why does the agent see its own sources? Under pressure from a skeptical user it once denied searches it had made, because earlier turns reached it as plain text. Each earlier answer now comes back with its record: the URLs it cited and what those pages said.

2 · "Has anything changed since Monday?"

A recheck is claim by claim. The agent knows what it said, when, and from which page, so it can re-check each claim and report held, changed or couldn't verify. It doesn't redo the research from scratch.

3 · What the user sees, and when

The page always shows what the agent is doing. A status line appears straight away and each search query as soon as it starts. With Claude's server-side search, thinking models (Sonnet, Opus) send the results and the answer together once the answer is written. Chat turns on Haiku stream word by word. The median turn across the eval is 6.6–6.9 s.
